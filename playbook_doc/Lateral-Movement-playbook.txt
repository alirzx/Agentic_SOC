1.	مقدمه
این Playbook با هدف مدیریت، تحلیل و پاسخ‌گویی ساخت‌یافته به رخدادهای مرتبط با تاکتیک Lateral Movement مطابق با چارچوب MITRE ATT&CK – TA0008 طراحی شده است. دامنه این مستند، کلیه Correlation Searchهایی را پوشش می‌دهد که منجر به شناسایی فعالیت‌های مشکوک با هدف حرکت بین سیستم‌ها در شبکه می‌شوند. در چارچوب MITRE ATT&CK، تاکتیک Lateral Movement به مجموعه‌ای از تکنیک‌ها اطلاق می‌شود که مهاجم از طریق آن‌ها تلاش می‌کند دسترسی خود را از یک سیستم (معمولاً اولین نقطه ورود یا  Foothold) به سیستم‌های دیگر در شبکه گسترش دهد. هدف مهاجم از این کار، دسترسی به دارایی‌های با ارزش‌تر )مانند دیتابیس‌ها، Domain Controllerها یا سیستم‌های حاوی اطلاعات حساس(، جمع‌آوری اعتبارنامه‌های بیشتر و پایدار کردن حضور خود در محیط است. مهاجمان برای حرکت جانبی اغلب از پروتکل‌ها و ابزارهای قانونی موجود در شبکه استفاده می‌کنند تا در ترافیک عادی محو شوند. این شامل استفاده از RDP، SMB، WinRM، SSH، اجرای دستورات از راه دور (مثل PsExec، WMI) یا بهره‌برداری از آسیب‌پذیری‌های سرویس‌ها می‌شود. تشخیص حرکت جانبی دشوار است زیرا ترافیک تولیدی ممکن است شبیه به فعالیت‌های ادمین‌ها یا ابزارهای مدیریت باشد.

2.	شرایط اجرا Play book
این Playbook زمانی فعال می‌شود که یکی از Correlation Searchهای مرتبط با تاکتیک Lateral Movement در Splunk Enterprise Security منجر به ایجاد Notable Event گردد و شواهد اولیه حاکی از تلاش برای اتصال یا اجرای کد روی سیستم‌های دیگر باشد. 
اجرای این Playbook محدود به ابزار خاصی نیست و هر رخدادی که شامل یکی از موارد زیر باشد، مشمول این فرآیند خواهد شد:
•	اتصالات از راه دور غیرمتعارف (RDP، SMB، WinRM)
•	اجرای دستورات یا کد روی سیستم‌های دیگر (Remote Code Execution)
•	استفاده از ابزارهای مدیریت از راه دور (PsExec، WMI، SCCM) توسط کاربران غیرمجاز.
•	کپی کردن فایل‌ها بین سیستم‌ها از طریق مسیرهای غیرعادی
در چنین شرایطی، تحلیلگر موظف است مراحل Playbook را به‌صورت مرحله‌به‌مرحله دنبال کند تا از تشخیص صحیح و جلوگیری از نشت اطلاعات حساس اطمینان حاصل کند.
3.	بررسی اولیه
تحلیلگر موظف است در اولین گام و بدون ورود به بررسی‌های پیچیده، فیلدهای کلیدی Notable Event و رویدادهای مرتبط را مطابق جدول زیر بررسی نماید:

ردیف	فیلد مورد بررسی	موارد مهم جهت بررسی
1	protocol	پروتکل استفاده شده (SMB, RDP, WinRM, SSH, WMI)

2	src_ip	آدرس IP مبدا (سیستمی که از آن حرکت آغاز شده)
3	dest_ip	آدرس IP مقصد (سیستم هدف)
4	dest_host	نام هاست مقصد (آیا DC، سرور فایل یا کلاینت است؟)
5	user	حساب کاربری استفاده شده برای احراز هویت در مقصد
6	process_name	نام فرآیندی که اتصال را ایجاد کرده مثلاً ( svchost.exe, mstsc.exe)
7	parent_process	فرآیند والد (آیا توسط ابزار مدیریتی یا اسکریپت اجرا شده؟)
8	share_name	نام Share شبکه در صورت استفاده از SMB
9	logon_type	نوع لاگین  (مثلاً Type 3 برای Network، Type 10 برای Remote Interactive)
10	status	وضعیت اتصال (موفق یا ناموفق)

هدف این مرحله، ایجاد درک اولیه از ماهیت رخداد و تصمیم‌گیری سریع برای ورود یا عدم ورود به فاز Investigation است.

4.	تشخیص False Positive یا True Positive بودن هشدار 
از آنجا که حرکت جانبی اغلب شبیه به فعالیت‌های مدیریتی است، احتمال False Positive وجود دارد. تمرکز بر روی "چه کسی"، "از کجا"، "به کجا" و "با چه ابزاری" کلید تشخیص است.

5.	شاخص های False Positive بودن هشدار
مهم‌ترین شاخص‌های False Positive عبارت‌اند از:
•	اتصالات RDP یا SMB توسط ادمین‌ها یا پشتیبانان برای مدیریت یا عیب‌یابی
•	اجرای وظایف زمان‌بندی‌شده (Scheduled Tasks) یا اسکریپت‌های اتوماسیون برای انتقال فایل‌ها
•	استفاده از ابزارهای مجاز مدیریت (مانند SCCM یا  Ansible) برای به روز رسانی سیستم‌ها
•	سرویس‌هایی که به‌صورت عادی با یکدیگر ارتباط دارند (مانند ارتباط وب‌سرور با دیتابیس)
در چنین شرایطی، بررسی مجوز کاربر و تکرارپذیری رفتار بسیار مهم است. 
سوالات کلیدی جهت تصمیم‌گیری
•	آیا کاربر مربوطه مجاز است که از سیستم مبدا به مقصد متصل شود؟آیا کاربر مربوطه مجاز به استفاده از ابزارهای پیشرفته دیباگ یا مدیریت است؟ 
•	آیا این اتصال در ساعات کاری و بر اساس تیکت پشتیبانی انجام شده است؟
•	آیا الگوی اتصال با Baseline رفتاری این کاربر هم‌خوانی دارد؟
•	آیا سیستم مقصد معمولاً هدف این نوع اتصالات قرار می‌گیرد؟

6.	Investigation دقیق توسط کارشناسان لایه ی بالا
این مرحله زمانی آغاز می‌شود که هشدار نشانه‌های حرکت جانبی مشکوک داشته باشد. هدف این فاز، تعیین اینکه آیا این حرکت بخشی از یک حمله است یا خیر.

7.	 بررسی والد فرزندی پراسس مشکوک
تحلیلگر باید بررسی کند که چه فرآیندی باعث ایجاد اتصال شده است. برای مثال، اجرای powershell.exe که فرزند winword.exe است و تلاش برای اتصال WinRM دارد، نشانه‌ای بسیار مشکوک از حرکت جانبی است. همچنین استفاده از ابزارهایی مانند psexec.exe یا wmic.exe باید به دقت بررسی شود.

8.	بررسی Command Line
تحلیل Command Line برای تشخیص نیت مهاجم حیاتی است. 
موارد زیر باید با دقت بررسی شوند:
•	وجود پارامترهای خاص در PsExec یا WMI برای اجرای دستور روی سیستم مقصد
•	استفاده از اعتبارنامه‌های متنی (Clear Text) در اسکریپت‌ها
•	دستوراتی که فایل‌های اجرایی را روی سیستم مقصد کپی می‌کنند. مثلاً copy  \\target\c$\temp\malware.exe
•	استفاده از ابزارهای غیراستاندارد برای انتقال فایل (مثل Certutil برای دانلود) 

9.	بررسی الگوی دسترسی  (Access Pattern)
بررسی رفتار شبکه و لاگ ها با دید موارد زیر:
•	آیا یک سیستم منبع (Source) به چندین سیستم مقصد متصل شده (Scanning  یا  Spread )
•	آیا تلاش‌های ناموفق متعدد برای اتصال به سیستم‌های مختلف وجود دارد (Credential Stuffing)؟
•	آیا پس از اتصال موفق، فعالیت‌های مشکوک مانند Credential Dumping)) روی سیستم مقصد رخ داده است؟

10.	ارتباط با تیم عملیات IT جهت Validation رخداد مذکور
پس از بررسی فنی، رخداد باید با تیم عملیات IT اعتبارسنجی شود. در صورت عدم تأیید فعالیت و مشاهده حرکت جانبی غیرمجاز، رخداد به Incident تبدیل شده و به تیم IR ارجاع داده می‌شود. 
نمونه رخدادهای رایج Lateral Movement
نوع رخداد	توضیح	مثال
Remote Services	استفاده از پروتکل‌های مدیریتی برای اجرای کد	استفاده از PsExec یا WMI برای اجرا
Remote Desktop Session	اتصال دسکتاپ از راه دور	اتصال RDP به سرور حساس
SMB/Windows Admin Shares	دسترسی به درایوهای اشتراکی اداری
 (C$, ADMIN$)	کپی کردن فایل از طریق C$
Internal Spearphishing
	ارسال ایمیل های داخلی برای سرقت اعتبار	ارسال لینک مخرب به کاربر داخلی
Pass the Hash

	استفاده از هش NTLM برای دسترسی

11.	پاسخ به رخداد
این مرحله زمانی فعال می‌شود که حرکت جانبی مخرب تایید شود. هدف Response، قطع مسیر حرکت مهاجم و جلوگیری از رسیدن او به دارایی‌های حیاتی است. 

12.	 اقدامات فوری
این اقدامات باید در کوتاه‌ترین زمان ممکن و متناسب با سطح ریسک رخداد انجام شوند.

1.	ایزوله سازی host 
سیستم مبدا (Source) و در صورت امکان سیستم مقصد (Destination) باید فوراً از شبکه ایزوله شوند. این کار مانع از ادامه حرکت جانبی مهاجم به سایر سیستم‌ها می‌شود.
2.	غیر فعال سازی یوزر مورد مخاطره
حساب کاربری که برای حرکت جانبی استفاده شده است (چه حساب کاربری عادی و چه حساب سرویس) باید فوراً غیرفعال یا Reset شود. اگر مهاجم موفق به سرقت هش شده باشد، تغییر رمز عبور نیز الزامی است.
3.	مسدود سازی پروتکل های مدیریت از راه دور
در صورت بروز حمله گسترده، می‌توان دسترسی RDP یا WinRM را روی ساب‌نت‌های آسیب‌دیده به‌صورت موقت مسدود کرد تا از گسترش حمله جلوگیری شود.
13.	جمع آوری شواهد و تعیین دامنه نفوذ
جمع‌آوری شواهد برای درک مسیر حرکت مهاجم ضروری است:
•	لاگ‌های ارتباطات شبکه (NetFlow) بین مبدا و مقصد
•	لاگ‌های امنیتی (Security Logs) روی سیستم مقصد برای بررسی لاگین‌ها و دسترسی‌ها
•	فایل‌هایی که ممکن است در جریان حرکت جانبی کپی شده باشند.
•	Memory Dump از سیستم مبدا برای استخراج اعتبارنامه‌های دزدیده شده

14.	ساخت IOC حمله ی مورد نظر
پس از تحلیل، IOCهای حمله استخراج می‌شوند که می‌توانند شامل موارد زیر باشند:
•	IP سیستم مبدا و مقصد
•	نام کاربری مورد استفاده برای حرکت جانبی
•	Hash فایل‌هایی که منتقل شده‌اند
این IOCها باید روی کل محیط Hunt شوند تا تمام سیستم‌هایی که مهاجم به آن‌ها نفوذ کرده است، شناسایی گردند

15.	بررسی Backup و بازگردانی
اگر سیستم‌ها در اثر حرکت جانبی و فعالیت‌های بعدی آلوده شده‌اند، IOCها باید روی بکاپ‌ها بررسی شوند. پس از اطمینان از سلامت، فرآیند Restore انجام می‌شود. همچنین باید مسیرهای حرکت جانبی (مانند پورت‌های باز غیرضروری یا سرویس‌های با دسترسی بالا) بررسی و ایمن‌سازی شوند.
